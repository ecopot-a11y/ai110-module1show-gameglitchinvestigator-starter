**Bug Reproduction Log**

Document at least 3 bugs you found. Add rows as needed.

### Bug 1: Hints point in the wrong direction

**Input/Trigger:** I submitted a guess that was higher than the secret number while "Show hint" was enabled.

**Expected Result:** If my guess was too high, I expected the game to tell me to guess lower.

**Actual Result:** The game identified the guess as "Too High" but displayed the hint "📈 Go HIGHER!" This sends the player in the wrong direction.

**Suspected Code Location/Cause:** `app.py`, `check_guess()`. When `guess > secret`, the function returns `"Too High"` but pairs it with `"📈 Go HIGHER!"`. The opposite hint is also used when the guess is too low.

### Bug 2: Secret number changes data type

**Input/Trigger:** I made multiple guesses on alternating attempts.

**Expected Result:** I expected the secret number to remain the same data type on every attempt so that my integer guess could be compared consistently with it.

**Actual Result:** The game behaves inconsistently on alternating attempts because the secret is converted from an integer to a string on even attempts. This can interfere with normal number comparisons and even the recognition of a correct guess.

**Suspected Code Location/Cause:** `app.py`, in the submit-guess logic immediately before `check_guess()`. The code uses `str(st.session_state.secret)` on even attempts but uses `st.session_state.secret` as an integer on odd attempts.

### Bug 3: Difficulty range is inconsistent

**Input/Trigger:** I selected Hard difficulty and started a new game.

**Expected Result:** Hard mode displays a range of 1 to 50, so I expected every new secret number to be between 1 and 50 and the instructions to display the same range.

**Actual Result:** The New Game code generates a secret between 1 and 100 regardless of the selected difficulty. The main instructions also always say "Guess a number between 1 and 100," even when Hard mode displays a range of 1 to 50.

**Suspected Code Location/Cause:** `app.py`, `get_range_for_difficulty()`, the displayed instructions, and the `new_game` section. The New Game code uses `random.randint(1, 100)` instead of the selected difficulty's `low` and `high` values.

## 4. What did you learn about Streamlit and state?

- How would you explain Streamlit "reruns" and session state to a friend who has never used Streamlit?

- Streamlit reruns the Python script from top to bottom whenever the user interacts with the app, such as clicking a button, entering a guess, or changing a setting. Normally, variables could be reset during these reruns, so st.session_state acts like the app’s memory and keeps important information available between interactions. In our guessing game, session state stores things such as the secret number, number of attempts, score, game status, and guess history. Without session state, the game could forget the secret number or reset the player's progress every time Streamlit reruns the app.
